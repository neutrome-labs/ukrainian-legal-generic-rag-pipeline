# ЄДРСР: CKAN → річний TSV-експорт → RTF → Markdown

## Встановлення

```bash
pip install -r requirements.txt
```

JSONL-прототип замінено адаптером реальних офіційних експортів. Кожен рік — окрема розпакована директорія з `documents.csv`, `courts.csv`, `instances.csv`, `regions.csv`, `judgment_forms.csv`, `justice_kinds.csv`, `cause_categories.csv`. Попри розширення CSV, роздільник — табуляція, кодування UTF-8. Великі `documents.csv` читаються потоково; лише невеликі довідники завантажуються в пам'ять.

## 1. Знайти та завантажити набори через CKAN

```bash
# Знайти всі річні набори (лише список, без завантаження)
python -m src.cli.edrsr_datasets
python -m src.cli.edrsr_datasets --years 2024 2025

# Завантажити ZIP і розпакувати в {cache}/exports/edrsr-data-YYYY/
python -m src.cli.edrsr_datasets --years 2024 2025 --download
python -m src.cli.edrsr_datasets --all-years --download

# Власний корінь кешу
python -m src.cli.edrsr_datasets --all-years --download --cache-dir /srv/edrsr
```

Використовується `https://data.gov.ua/api/3/action/package_search` з пагінацією, фільтром офіційного розпорядника ДСА та точною перевіркою назви «Єдиний державний реєстр судових рішень за YYYY рік» (крапка необов'язкова). Ресурси ZIP беруться з відповіді CKAN, URL не конструюються за роком. Якщо в наборі декілька ZIP — вибирається найновіший `last_modified`; неоднозначні однакові дати спричиняють помилку. Обраний resource ID, розмір і дата показуються перед завантаженням.

17.09.2026 перевірено 21 набір (2006–2026); сумарний заявлений розмір ZIP приблизно 5.4 GB. Після розпакування потрібно значно більше місця. Це **метадані з посиланнями**, а не завантажені тексти всіх рішень. DataStore для цього процесу не потрібен.

Вихід: `{cache}/exports/edrsr-data-YYYY/` (за замовчуванням `cache/edrsr/exports/`). Існуючі директорії, включно з завантаженими вручну, **не перезаписуються**. Для нової версії використовуйте інший `--cache-dir`. Це не автоматична синхронізація змін. Невдалий ZIP не публікується; тимчасові файли очищаються. Ліміти за замовчуванням: 2 GiB завантаження, 10 GiB розпакованих даних на архів. ZIP після розпакування видаляється. Пошкоджені/невідповідні архіви відхиляються.

`_source.json` зберігає CKAN dataset/resource ID, URL, ліцензію, час отримання й SHA256 архіву. Поля походження переносяться в метадані Markdown. Для вручну завантажених каталогів без цього файла походження не вигадується: лишається назва каталогу й URL рішення/тексту.

## 2. Перевірити таблиці без отримання текстів

```bash
python -m src.cli.edrsr 2025 --preview --limit 10
python -m src.cli.edrsr 2024 2025 --preview --limit 10
```

Рік без слеша розкривається як `{cache}/exports/edrsr-data-YYYY/` (default: `cache/edrsr/exports/`). Можна передати і повний шлях до власної директорії. Preview друкує JSON-рядки з метаданими та розшифрованими кодами. Не звертається до R2, не завантажує тексти й не пише кеш. Без `--limit` preview показує 10 рядків.

## 3. Завантажити тексти та записати Markdown

```bash
# Малий запуск; Markdown у {cache}/documents/edrsr/
python -m src.cli.edrsr 2025 --limit 10

# Декілька років; порядок аргументів визначає порядок обробки
python -m src.cli.edrsr 2024 2025 --limit 100

# Повні шляхи до власних каталогів також приймаються
python -m src.cli.edrsr /srv/edrsr/exports/edrsr-data-2019 --limit 50

# Відновити, не завантажуючи вже оброблені ID
python -m src.cli.edrsr 2025 --skip-existing

# Лише раніше закешовані документи (без мережі)
python -m src.cli.edrsr 2025 --offline --limit 10

# Явно завантажувати результат до R2 (замість {cache}/documents)
python -m src.cli.edrsr 2025 --r2 --limit 10
```

`--limit` — максимальна кількість **вхідних рядків сумарно**, до фільтрів статусу/існуючих ID. `--limit 0` нічого не читає. Без ліміту імпорт читає всі рядки: це може бути дуже довго. Рядки зі статусом, відмінним від `1`, не завантажуються, навіть із кешу; це консервативна політика публічного імпорту. Вони **не видаляють** раніше індексовані документи.

Всі артефакти живуть в одному корені кешу: `cache/edrsr/{exports,documents}` та RTF-кеш `cache/edrsr/`. Річні директорії — `exports/edrsr-data-YYYY/`; Markdown — `documents/edrsr/decisions/{doc_id}.md` і `documents/edrsr/_metadata/decisions/{doc_id}.json`. Номер справи не використовується як унікальний ID. Один повний документ — один Markdown. `--skip-existing` пропускає ID навіть після зміни тексту; це resume, не оновлення версій. Завершені записи залишаються після помилки. Кеш також не виявляє зміни тексту за незмінним URL: для оновлення потрібен новий/очищений кеш.

Тексти отримуються лише з HTTPS `od.reyestr.court.gov.ua/files/*.rtf` або `*.html`. `--delay` — затримка між завантаженнями, за замовчуванням 6 секунд; це консервативне налаштування, не підтверджена квота сервера. Ліміт файла — 20 MiB. Перенаправлення, HTTP-помилки, сторінки відмови замість документа і некоректний текст зупиняють процес; повторних запитів в обхід обмежень немає. Конвертер підтримує RTF Unicode, CP1251 та legacy HTML Windows-1251 (META-заголовки з персональними даними свідомо не копіюються в текст/метадані).

## Перевірено та обмеження

- Live CKAN discovery і download/extract найменшого архіву за 2006 рік успішні.
- Реальний запис `124185778` з вашого експорту 2025: lookup суду, завантаження RTF, конвертація українського тексту й локальний Markdown успішні. Пропуск уже збереженого ID працює до завантаження.
- **Старі роки підтримуються з обмеженнями.** Discovery, ZIP і preview працюють; тексти `.rtf` та legacy `.html` (Windows-1251) конвертуються. Перший запис 2006 року успішно імпортовано, включно з RTF-конвертацією та provenance. Деякі legacy сторінки дублюють текст російською; це вихідні дані, не помилка конвертера. Нечитабельні файли все ще зупиняють процес.
- Семантику старих схем, повноту наборів, доступність усіх текстів, режим дозволеного масового доступу та статуси потрібно перевірити перед великим запуском. API каталогу не означає необмежений доступ до текстового сервера.
- Видалення/обмеження доступу, контроль версій, дискова база стану замість повного списку ID, фільтри за судом/датою та масштабна синхронізація — наступні етапи. Не змішуйте «чинність закону» зі статусом публікації рішення.
- Ліміти та вартість AI Search і фільтрацію метаданих перевіряйте окремо; не припускайте автоматичної підтримки всіх полів YAML.
